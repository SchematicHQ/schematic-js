# v3: components on the catalog API

The v3 surface replaces the `/components/hydrate` data path with the catalog
API: small hooks that fetch typed server data, pure domain-model derivations
that turn it into render-ready structures, and code-first elements built
from both. Everything ships through `@schematichq/schematic-components/v3` (the
elements) and `@schematichq/schematic-react` (the hooks and derivations the
elements are made of). The legacy embed surface (`SchematicEmbed`,
`EmbedProvider`, the drag-and-drop builder) is untouched.

Three ways in, at whatever altitude fits:

1. **Drop-in elements** — mount `<PricingTable />` and go.
2. **Hooks + derivations** — call `useCatalog()` and
   `derivePlanOfferings()` yourself, render your own markup.
3. **Hooks only** — take the typed server data and do everything by hand.

## Setup

```tsx
import { SchematicProvider } from "@schematichq/schematic-react";

<SchematicProvider
  publishableKey="api_..." // anonymous catalog (pricing pages)
  accessToken={getCustomerToken} // company data (portals); string or async provider
  locale="de-DE" // optional; defaults to navigator.language
>
  <App />
</SchematicProvider>;
```

Both credentials can be held at once: flag checks and the websocket keep
using the publishable key, the company data needs the token, and the
catalog follows the token unless you ask for the public shape
(`useCatalog({ mode: "public" })`, `<PricingTable mode="public" />`).

The access token is issued by your backend with a secret key and identifies
one company. It can arrive after mount (post-login); hooks that need it
report an error state until it does, then load automatically. If the same
provider function starts authenticating a _different_ company (re-login),
call `useSchematicCustomerClient()?.resetSession()`.

## Drop-in elements

```tsx
import {
  CreditUsage,
  IncludedFeatures,
  Invoices,
  MeteredFeatures,
  PlanManager,
  PricingTable,
  SchematicStyles,
  UpcomingBill,
} from "@schematichq/schematic-components/v3";

<>
  <SchematicStyles /> {/* once; or bring your own CSS for .schematic-* */}
  <PricingTable
    onSelectPlan={(plan, { period, currency }) =>
      startCheckout(plan.id, period, currency)
    }
    showAsMonthlyPrices
  />
  <PlanManager onChangePlan={openPlanPicker} />
  <IncludedFeatures />
  <MeteredFeatures visibleFeatures={["feat_api_calls", "feat_seats"]} />
  <CreditUsage onBuyBundle={(bundle) => startBundleCheckout(bundle.id)} />
  <Invoices limit={5} /> {/* pages of 5; "Load more" appends the next */}
  <UpcomingBill />
</>;
```

Display toggles (`showPeriodToggle`, `showAsMonthlyPrices`, `showCredits`,
`showFeatureDescription`, `showHardLimit`, `showZeroPriceAsFree`) are props
on `PricingTable`, not catalog configuration — the catalog API returns
facts, and how you present them is yours. `showHardLimit` surfaces the hard
limit behind an overage entitlement's soft limit ("then $0.10/call, up to
5,000").

Every element takes `className` (appended to its `schematic-*` root class)
and `locale`. On a company catalog, a plan the company may trial renders a
"Start N-day trial" call to action (`plan.canTrial` / `plan.trialDays` in
`onSelectPlan`); a plan the company is over the limits of, or an add-on
that isn't available on its current plan, renders a disabled call to action
in both the link and button forms. The period toggle offers recurring
periods only: one-time plans and add-ons are priced at their one-time price
whatever it shows, and `onSelectPlan` receives the period the card is priced
at (`"one_time"` for those). A failed request renders the error with a
Retry button — errors are never cached, so the retry re-runs the request.
`CreditUsage` offers "Buy more" for each credit the catalog sells a bundle
of: pass `onBuyBundle` for a handler or `buyMoreUrl` for a link (the bundle
and credit IDs are appended as `bundle_id` / `credit_id`).

Every element renders through one status frame: a skeleton while pending,
an inline error (with the API's message) when there is nothing to show, the
last good data kept across a failed refetch, and an element-specific empty
state. A 404 from an account that doesn't have the catalog API enabled
surfaces as that error.

Theming: override the `--schematic-*` custom properties anywhere above the
elements (the defaults are declared on `:root` with zero specificity via
`:where`, so any declaration of yours wins — on `:root`, `body`, or a
wrapper around the elements):

```css
.my-billing-page {
  --schematic-accent: #7c3aed;
  --schematic-radius: 12px;
}
```

The default stylesheet ports the v2 embed design: `--schematic-primary`
(black) drives CTAs, badges, and the current-plan outline;
`--schematic-accent` (blue) drives links, meter fills, and notices;
`--schematic-shadow`, `--schematic-card-padding`, and `--schematic-border`
shape the cards; `--schematic-meter-track` and `--schematic-warning` color
the usage meters.

Fonts: the defaults reference **Manrope** (`--schematic-font-heading`) and
**Public Sans** (`--schematic-font-body`) but the stylesheet never loads
font files — load them in the host app or override the variables. In Next.js:

```tsx
import { Manrope, Public_Sans } from "next/font/google";

const manrope = Manrope({ subsets: ["latin"] });
const publicSans = Public_Sans({ subsets: ["latin"] });

<div
  style={
    {
      "--schematic-font-heading": manrope.style.fontFamily,
      "--schematic-font-body": publicSans.style.fontFamily,
    } as React.CSSProperties
  }
>
  <SchematicStyles />
  <PricingTable />
</div>;
```

| Element            | Data                                          | Needs token             |
| ------------------ | --------------------------------------------- | ----------------------- |
| `PricingTable`     | `useCatalog`                                  | no (decorated with one) |
| `PlanManager`      | `useCompany` + `useCatalog` (post-trial plan) | yes                     |
| `IncludedFeatures` | `useFeatureUsage`                             | yes                     |
| `MeteredFeatures`  | `useFeatureUsage`                             | yes                     |
| `CreditUsage`      | `useCreditBalances`                           | yes                     |
| `Invoices`         | `useInvoices`                                 | yes                     |
| `UpcomingBill`     | `useUpcomingInvoice`                          | yes                     |

The elements render plain English copy. If you localize, drop down one
level — the derivations are copy-free by design.

## Hooks + derivations (your markup)

Every hook returns `{ data, error, isPending, isRefetching, refetch }`;
`useInvoices` adds `hasMore` and `fetchMore()`. Derivations are pure:
`(data, selection) → domain model`, with all numerals already
`Intl`-formatted for your locale. Sentence assembly is yours.

Refreshing is explicit: nothing refetches on a timer or on window focus.
After a plan change, call `useSchematicCustomerClient()?.invalidateAll()`
(or a hook's `refetch()`).

### Pricing table

```tsx
import {
  derivePlanOfferings,
  useCatalog,
  type PricePeriod,
} from "@schematichq/schematic-react";

const Pricing = () => {
  const { data, error, isPending } = useCatalog(); // or useCatalog({ mode: "public", catalogId })
  const [period, setPeriod] = useState<PricePeriod>();

  if (isPending) return <Spinner />;
  if (error) return <ErrorNote error={error} />;

  const vm = derivePlanOfferings(data, {
    period,
    locale: "de-DE",
    showAsMonthlyPrices: true,
  });
  return (
    <>
      {vm.togglePeriods.map((p) => (
        <button
          key={p}
          onClick={() => setPeriod(p)}
          aria-pressed={p === vm.selectedPeriod}
        >
          {p}
        </button>
      ))}
      {vm.plans.map((plan) => (
        <article key={plan.id}>
          <h3>{plan.name}</h3>
          {plan.price.kind === "priced" && <b>{plan.price.price.formatted}</b>}
          {plan.price.kind === "free" && <b>Free</b>}
          {plan.savingsPercentVsMonthly && (
            <i>save {plan.savingsPercentVsMonthly}%</i>
          )}
          <ul>
            {plan.entitlements.map((row) => (
              <li key={row.feature.id}>
                {/* row.kind: priced | tiered | credit_rate | credit_limit | numeric | unlimited | boolean */}
                {row.kind === "unlimited"
                  ? `Unlimited ${row.featureLabel}`
                  : null}
                {row.kind === "numeric"
                  ? `${row.formattedLimit} ${row.featureLabel}`
                  : null}
              </li>
            ))}
          </ul>
        </article>
      ))}
    </>
  );
};
```

### Usage meters

```tsx
import { deriveUsage, useFeatureUsage } from "@schematichq/schematic-react";

const { data } = useFeatureUsage();
const meters = (data ?? []).map((row) =>
  deriveUsage(row, { warningPercent: 80 }),
);
// meter: { featureName, used, limit, percent, state: "ok"|"warning"|"over_limit",
//          formattedResetsAt, formattedCurrentCost, source: "plan"|"company",
//          entitlement: the same decision tree the pricing table uses }
```

The warning state is driven by `warningPercent` when you pass one
(`MeteredFeatures` forwards its prop); otherwise by the entitlement's own
`warning_threshold` when the plan author configured one; otherwise at 90%.
`formattedCurrentCost` is only present for pay-as-you-go and overage
entitlements — the server bills every unit for the former and only the usage
above the soft limit for the latter — and is formatted in the server's
`current_cost_currency` (the subscription currency's metered price).

### Credits

```tsx
import {
  deriveCreditBalances,
  useCreditBalances,
} from "@schematichq/schematic-react";

const { data } = useCreditBalances();
const credits = deriveCreditBalances(data?.balances ?? []);
// credit: { creditName, used/total/remaining (+formatted), percentUsed, formattedExpiresAt,
//           grants: [{ source: { reason, planName?, bundleName? }, formattedExpiresAt }] }
```

### Invoices and the next bill

```tsx
import {
  deriveInvoiceList,
  deriveUpcomingInvoice,
  useInvoices,
  useUpcomingInvoice,
} from "@schematichq/schematic-react";

const { data, hasMore, fetchMore } = useInvoices({ limit: 10 });
const invoices = deriveInvoiceList(data?.rows ?? []);
// row: { formattedDate, formattedAmount ("($50.00)" for credit notes), status, url }
// hasMore → render a "Load more" control that calls fetchMore()

const bill = useUpcomingInvoice().data;
const vm = bill && deriveUpcomingInvoice(bill);
// vm: { formattedSubtotal, discounts, formattedBalanceApplied, formattedAmountDue, formattedDueDate }
```

### Plan summary and notices

```tsx
import {
  derivePlanSummary,
  useCatalog,
  useCompany,
} from "@schematichq/schematic-react";

const { data: company } = useCompany();
const { data: catalog } = useCatalog(); // supplies the post-trial plan for the trial notice
const vm = company && derivePlanSummary({ company, catalog });
// vm.currentPlan: { name, formattedPrice, period, isCustom }, vm.subscription: RFC3339 facts,
// vm.notice.kind: trialing | will_cancel | custom_plan_pending | scheduled_downgrade
```

## Server rendering

The one-shot fetchers return plain data for React Server Components or
`getServerSideProps`; hand it to the provider as `initialData` and the first
client render is complete instead of pending:

```tsx
import { fetchCatalog, fetchCompany } from "@schematichq/schematic-js";

const [catalog, company] = await Promise.all([
  fetchCatalog({ publishableKey, accessToken }),
  fetchCompany({ accessToken }),
]);

<SchematicProvider
  publishableKey={publishableKey}
  accessToken={accessToken}
  initialData={{ catalog, company }}
>
  <PlanManager />
</SchematicProvider>;
```

Hooks never fetch during server render; without `initialData` they report
`isPending` on the server and fetch on the client. The styled elements are
DOM-only; React Native consumers use the hooks and derivations directly.

## Fixtures and contract checks

`src/customer/goldens/*.json` in `@schematichq/schematic-js` are real
responses recorded by the API's route tests (`yarn sync-goldens` copies them
from a local `schematic-api` checkout after `UPDATE_GOLDENS=1 task test:run`
there). `goldens.spec.ts` decodes them through the generated clients and
runs every derivation over them, so a required-field change on either side
fails in CI before it fails in a browser.

## Raw data

The hooks return the catalog API's typed responses; the generated clients
are also exported (`publicApi`, `customerApi` from
`@schematichq/schematic-js`) if you need to call the endpoints directly.
